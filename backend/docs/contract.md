# Churn Guard Data & API Contract
*Agreed Contract across Person A (Frontend), Person B (Backend & PayPal), and Person C (AI Auditor).*

---

## 1. Subscription Schema

All subscription objects returned by `GET /api/subscriptions` or ingested via `POST /api/ingest` conform to this contract:

```typescript
export interface Subscription {
  id: string;                         // Unique ID (e.g., "sub-tunebox")
  name: string;                       // Service name (e.g., "TuneBox Premium")
  category: string;                   // Category (e.g., "Music & Audio", "Streaming", "Fitness")
  price: string;                      // Formatted string (e.g., "10.99")
  currency: string;                   // ISO 4217 code (default: "USD")
  interval: "MONTH" | "YEAR";         // Billing cycle interval
  status: "APPROVAL_PENDING" | "ACTIVE" | "SUSPENDED" | "CANCELLED" | "EXTERNAL";
  source: "paypal" | "external";      // "paypal" = live PayPal management; "external" = bank/statement export
  managedByPaypal: boolean;           // true if controllable via PayPal Subscriptions API
  paypalSubscriptionId: string | null;// PayPal Subscription ID (e.g., "I-BW452GLLEP1G") or null
  planId: string | null;              // PayPal Plan ID currently active
  downgradePlanId: string | null;     // Lower tier Plan ID for 1-click downgrade recommendation
  nextBillingTime: string | null;     // ISO 8601 (e.g., "2026-11-27T00:00:00.000Z") or null
  trialEndsAt: string | null;         // ISO 8601 trial expiration or null
  lastUsedAt: string | null;          // ISO 8601 last usage activity or null
  createdAt: string;                  // ISO 8601
}
```

### External (Audit Only) Subscriptions Rule
When `source === "external"`, the subscription was parsed from a raw bank export or CSV and is **not** managed by PayPal.
- Attempting `POST /api/subscriptions/:id/pause`, `/resume`, `/cancel`, or `/downgrade` will return:
  ```json
  // HTTP 409 Conflict
  {
    "error": {
      "code": "AUDIT_ONLY",
      "message": "Audit only - not managed through PayPal"
    }
  }
  ```

## 2. Alert Schema

Alerts generated by the AI parser (Person C) or PayPal lifecycle webhooks (Person B):

```typescript
export interface Alert {
  id: string;                         // Unique alert ID (e.g., "alert-overlap-music")
  subscriptionId: string;             // Associated subscription id
  type: "trial_ending" | "price_increase" | "unused" | "overlap" | "payment_failed";
  severity: "low" | "medium" | "high";
  message: string;                    // Short user-facing alert headline
  recommendation: "pause" | "downgrade" | "cancel" | "keep";
  reason: string;                     // Detailed AI rationale explaining why this action saves money
  createdAt: string;                  // ISO 8601
  read: boolean;                      // Read status
}
```

## 3. Endpoints for Frontend (Person A)

Base URL: `http://localhost:3000` (or `VITE_API_URL`)

### Authentication & Demo Mode
- In `DEMO_MODE=true` (default), **no authentication is required**. You can omit the `Authorization` header completely.
- If testing authentication:
  - `POST /api/auth/login`
  - Body: `{ "email": "demo@churnguard.local", "password": "demopassword" }`
  - Returns: `{ "token": "<JWT>", "user": { "id": "...", "email": "..." } }`
  - Pass header: `Authorization: Bearer <JWT>`

### Subscriptions
- `GET /api/subscriptions` &rarr; Returns `Subscription[]`
  - In real sandbox mode, PayPal status is cached for 30s. Pass `?sync=true` to force a live sync.
- `GET /api/subscriptions/:id` &rarr; Returns single `Subscription`
- `POST /api/subscriptions/:id/pause`
  - Body: `{ "reason": "Customer requested pause" }`
  - Returns: `{ "success": true, "subscription": { ... } }`
- `POST /api/subscriptions/:id/resume`
  - Body: `{ "reason": "Customer requested resume" }`
  - Returns: `{ "success": true, "subscription": { ... } }`
- `POST /api/subscriptions/:id/cancel`
  - **Required Body**: `{ "confirm": true, "reason": "Optional reason" }`
  - Returns: `{ "success": true, "subscription": { ... } }`
- `POST /api/subscriptions/:id/downgrade`
  - Body (optional): `{ "targetPlanId": "P-...", "reason": "..." }`
  - Returns: `{ "success": true, "subscription": { ... }, "approveUrl": "https://www.sandbox.paypal.com/..." }`
  - *Note: If PayPal requires buyer consent for plan change, `approveUrl` is returned. Direct the buyer to open it.*
- `GET /api/subscriptions/:id/transactions`
  - Returns: `{ "transactions": [ { "id": "...", "status": "COMPLETED", "amount": { "currency": "USD", "value": "15.99" }, "time": "..." } ] }`

### Alerts
- `GET /api/alerts` (optional `?unread=true`) &rarr; Returns `Alert[]`
- `POST /api/alerts/:id/read` &rarr; Marks alert read. Returns `{ "success": true, "alert": { ... } }`

### Server-Sent Events (Real-time updates)
- `GET /api/events`
  - Content-Type: `text/event-stream`
  - Event types emitted:
    - `subscription_updated`: Data is the updated `Subscription` object.
    - `alert_created`: Data is the new `Alert` object.
    - `webhook_received`: Data is `{ eventId, eventType, resourceId }`.

### Demo Utilities
- `POST /api/demo/reset` &rarr; Resets DB to clean default mock fixtures.
- `GET /api/health` &rarr; Returns `{ "status": "healthy", "mode": "mock" | "real", "paypalEnv": "sandbox" }`.

## 4. Endpoints for AI Auditor / Parser (Person C)

### Ingest Parsed Statement / Subscriptions
- `POST /api/ingest`
- Payload: Array of subscriptions (or `{ "subscriptions": [...] }`):
  ```json
  [
    {
      "name": "Equinox Gym",
      "category": "Fitness",
      "price": "280.00",
      "currency": "USD",
      "interval": "MONTH",
      "lastUsedAt": "2026-09-01T00:00:00.000Z"
    }
  ]
  ```
- Subscriptions are upserted as `source: "external"` and `managedByPaypal: false` unless a `paypalSubscriptionId` is explicitly provided.
- Emits `subscription_updated` event on SSE for each item.

### Push Generated Alerts
- `POST /api/alerts`
- Payload: Single alert object or an array of alert objects:
  ```json
  [
    {
      "subscriptionId": "sub-fitclub",
      "type": "unused",
      "severity": "high",
      "message": "FitClub unused for 74 days",
      "recommendation": "pause",
      "reason": "Zero gym visits detected on statement. Pausing saves $49/mo."
    }
  ]
  ```
- Emits `alert_created` on SSE in real-time.
